# Repository Guide

## Boundaries

- Treat `src/domain` as the invariant layer and keep browser/DOM details outside it.
- Keep use cases in `src/application`, browser adapters in `src/infrastructure`, DOM rendering in `src/presentation`, and coordination in `src/controller`.
- Keep files under 200 lines, functions under 60 lines, and ESLint complexity at 10 or less.
- Use test-first changes. Run the focused failing test before implementation, then the full relevant suite.

## Question Data

- Keep questions and their embedded `answerSources` under `data/questions`; keep interview records under `data/evidence`.
- Never hand-edit `questions.js`; it is generated by `pnpm questions build`.
- Browser runtime records must not contain companies, interview evidence, or URLs.
- `data/evidence` is maintenance-only and must never be included in the Pages artifact.

## Generated Assets

- Never hand-edit `app.js` or `styles.css`; build them from `src/main.ts` and `src/styles/main.css`.
- Run `pnpm build` after source or authoring-data changes and commit the resulting public assets together.
- Generated text uses LF. Do not override `.gitattributes` with platform-specific line endings.

## Commands

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm questions search --query RAII
pnpm questions evidence --id 001
pnpm questions stats
pnpm questions apply --file changes.json --dry-run
pnpm questions apply --file changes.json
pnpm questions build
pnpm questions check
pnpm verify
```

`pnpm verify` builds public assets, type-checks, lints, runs coverage and E2E tests, and checks the generated question runtime.
